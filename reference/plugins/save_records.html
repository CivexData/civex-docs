    civex.save_records@1 (Save as records)

    Save the rows of a table or a set of files as records, one record for each row or file. When a matching record already exists, If a matching record already exists (if_exists) says what happens:

    if_exists A row or file whose record is there One whose record is not
    update (default) changes the record, only what the table or file brings makes a record
    skip leaves the record as it is (counted in skipped, named in skipped_rows) makes a record
    add_new never looks for a match: always makes another record makes a record

    Running the same table or files again changes nothing: the records are matched, found unchanged (unchanged), left without history and without starting any workflow.

    Give it either rows (from Table) or files (from Files), not both.

    Plugin ID: civex.save_records@1
    Category: save
    Capabilities: read, write_records

    Config

    Field Type Required Default Description
    schema string yes The kind of record to save. In the YAML, schema:.
    if_exists string no update update: change the record, only what the table or file brings. skip: leave it as it is. add_new: always make a new record, never looking for a match.
    match_on array no The field(s) a row or file and a record must agree on to be the same record. For a table, empty means the kind's first unique key, or, when it has none, every row makes a new record. For files, one field, compared with the key in the file's name.
    filename_pattern string | null no null Files only: which part of a file's name says which record it belongs to, with one capture group, e.g. sel_(\d+). Build it from an example.
    file_field string | null no null Files only: the file field of each record.
    field_mapping object no Tables only: maps table column names to field names. Empty means columns are used as field names directly.
    as_written boolean no False Tables only: every cell is the text it shows. Blank cells are left out and each other cell becomes the value its field holds (a whole number, a date, yes or no); a row with a cell that can't be that is skipped and named.
    first_row integer no 1 Tables only: the number said of the first row when a row is named (2 for the first row under a heading row).
    dataset string no "" Collection to save records in. Empty: the collection of the record the workflow runs on.
    parent_record_id string no "" The record to match within and save inside. Empty: the record the workflow runs on.

    Inputs

    Name Type Required Description
    rows table no The table to save, one record for each row. Its columns go into the fields of the same name, unless Columns to fields says otherwise.
    files files no The files to save, one record for each file, with the file in the field chosen in Put the file in field.
    earlier table no Rows that come before the table, already dealt with (same columns): their keys count when a repeated one is looked for, so a table saved in parts treats repeats as one saved whole. Nothing is saved from them.

    Outputs

    Name Type Required Description
    created number yes How many records it made.
    updated number yes How many existing records it changed.
    unchanged number yes How many existing records already held what was brought.
    skipped number yes How many rows or files were not saved.
    skipped_rows list yes Why each row or file not saved was left out: no value to match by, a value repeated, several records with it, a matching record left alone, or a value the record refused.
    unmatched list no Files with no key in their name, or whose record could not be saved.
    ambiguous list no Files left alone because another file in the same run has the same key (one record holds one file), each with the files it clashes with.

    Tables

    - id: sheet
  plugin: civex.table@1
  config:
    field: sample_sheet

- id: save
  plugin: civex.save_records@1
  config:
    schema: Sample
    dataset: survey-2024
    match_on: [number]
    field_mapping:
      "Taken at": taken_at
      "Depth (m)": depth
      "Sample": number
  inputs:
    rows: sheet.table

    How a row finds its record

    Match on (match_on) names the fields a row and a record must agree on to be the same record. They are the kind's own fields, named after Columns to fields (field_mapping) is applied (number above, not the column Sample). A row is matched only against records of that kind inside the same record (Inside record, else the record the workflow runs on), in the collection it writes to.

    • Left empty, the kind's first unique key is used (the run log says so).
    • Left empty on a kind with no unique key, every row makes a new record.

    Values are compared the way a unique key compares them: a number by its value (12 and 12.0 are the same; a column with a blank cell reaches the step as decimals), so a table re-read from the same file always finds its records. A number given for a text field is written and matched as its text ("12").

    What an update keeps

    An update changes only the columns in the table. Every other field on the matched record (a file, values computed by another workflow) is left exactly as it is, and an empty cell leaves its field alone instead of clearing it.

    Rows it leaves out

    A row is skipped, counted in skipped and named in skipped_rows (the run shows them as problems), when:

    • a field it is matched by is empty in that row;
    • its key repeats an earlier row of the same table (the first is saved; the step never guesses which of two rows is right);
    • several records already have its key;
    • if_exists is skip and its record is there;
    • the record refuses its values (a restriction, a required field, a unique key).

    The other rows are saved.

    Files

    - id: wavs
  plugin: civex.files@1
  config:
    source: run
    label: Sequence WAV files

- id: put
  plugin: civex.save_records@1
  config:
    schema: sequence_selection
    if_exists: update
    match_on: [selection_number]       # compared with the key in the file name
    filename_pattern: 'sel_(\d+)'      # one capture group: the key
    file_field: seq_wav_file           # where the file goes
  inputs:
    files: wavs.files

    The key in each file's name (filename_pattern) is a regular expression with one capture group; the captured text is compared with the one Match on field (01 and 1 are the same number). Put the file in field (file_field) is a file or file-list field: a file-list field gets the file added (once; the same content is never added twice), a file field holds the file itself. A file whose key matches no record makes one, with the key in the match field.

    • With add_new, no key is needed: every file makes a record (the pattern, if given, still fills the match field).
    • Two files in one run with the same key are not attached (one record holds one file): they are listed in ambiguous, and nothing wrong is written. That is almost always a pattern that reads too little of the name (sel_(\d{2}) takes 14 from both selection 14 and 149).
    • A file whose name has no key is listed in unmatched, with files whose record could not be saved.
